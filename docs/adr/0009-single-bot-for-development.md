# 0009. Один бот для разработки и для боя

- **Статус:** Принято (решение владельца)
- **Дата:** 2026-10-06
- **Контекст:** план (`docs/PLAN_FROM_SCRATCH.md`, §2 и P.4) предполагал отдельного dev-бота для разработки и «будущего боевого» `@romchik_infomat_bot`. Владелец решил тестировать на том же боте: реальных учеников и данных до запуска нет (ADR 0006), второй бот только усложняет настройку.
- **Решение:**
  - До боевого запуска локальная разработка и ручные проверки идут на `@romchik_infomat_bot` (`BOT_MODE=polling`, токен только в локальном `.env.local`).
  - Окружение `staging` по-прежнему использует **отдельного** бота (`docs/10` §1): это отдельный сервер и отдельные данные, к локальной разработке не относится.
  - **Условие перед боевым запуском (T9.10):** токен перевыпускается в BotFather (`/revoke`), новый токен вносит в `.env` prod-сервера только владелец. Прежний токен после этого недействителен.
  - После запуска локальная разработка идёт на отдельном dev-боте (создаётся в этот момент), на боевой токен локально не переходим.
- **Почему перевыпуск обязателен:**
  - Один токен нельзя использовать одновременно локально (polling) и на сервере (webhook): локальный запуск вызывает `deleteWebhook` и отключит боевой webhook, а Telegram отвечает ошибкой конфликта на параллельные `getUpdates`.
  - Токен долго жил на рабочей машине, в логах терминала и инструментах разработки; перевыпуск снимает риск утечки.
- **Последствия:**
  - Пока бот публичный, ему может написать кто угодно: гостю доступны только приветствие, каталог и контакт преподавателя. Тестовых учеников приглашают только владелец и тестовые аккаунты.
  - Тестовые данные (ученики, приглашения) в БД разработки не переносятся в prod (`docs/PLAN_FROM_SCRATCH.md`, T9.10: отдельная БД, сиды только справочники).
  - Настройки бота в BotFather (меню, описание) меняются на «боевые» уже сейчас; финальное оформление — в T9.10.
