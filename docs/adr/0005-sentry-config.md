# 0005. Конфигурация Sentry (T0.04)

- **Статус:** Принято
- **Дата:** 2026-10-06
- **Задача:** T0.04 (`docs/PLAN_FROM_SCRATCH.md`)
- **Контекст:** `docs/09` §4 требует минимизации персональных данных и запрещает передачу PII, `docs/03` упоминает Sentry в обработке неожиданных ошибок. Нужно зафиксировать, когда Sentry активен и что он может отправлять.
- **Решение:**
  - **Sentry выключен в разработке** (локально и в тестовых окружениях инициализация не выполняется; `SENTRY_DSN` при `APP_ENV=dev` игнорируется).
  - В production Sentry активен, но **без PII** на сервере: `send_default_pii=False`; из событий фильтруются токены и `initData`; в URL перед отправкой удаляются чувствительные значения; в консоль/Sentry не попадают персональные данные.
  - Производственный DSN — из `.env` / GitHub Secrets, никогда не хардкодится.
- **Последствия:** инициализация Sentry только для `APP_ENV=prod`; фильтры — общие для бэкенда и фронтенда (фронтенд передаёт в Sentry минимально необходимые, без PII, события).
