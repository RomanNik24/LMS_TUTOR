# 05. Логика бота, FSM, клавиатуры и уведомления

Бот — точка входа, канал уведомлений и быстрый доступ к данным. Основной интерфейс — веб-приложение (Mini App / сайт). Бот на Aiogram 3.x, вызывает `services/` напрямую.

## 1. Состояния пользователя в боте
Определяются по `telegram_id` через middleware `AuthMiddleware`, который кладёт в данные хэндлера `current_user` (или `None` для гостя).

| Состояние | Условие |
|---|---|
| Гость | `telegram_id` не найден в `users` или пользователь `is_active = false` |
| Ученик | `role = student`, активен |
| Персонал | `role in (owner, manager)`, активен |

Архивный пользователь (`is_active = false`) обрабатывается как гость; ему показывается нейтральное сообщение «Доступ закрыт, обратитесь к преподавателю».

## 2. Команды

| Команда | Гость | Ученик | Персонал |
|---|---|---|---|
| `/start` | Приветствие + «Каталог услуг», «Связаться с преподавателем» | Приветствие по имени + меню ученика | Приветствие + меню персонала |
| `/start inv_<token>` | Принятие приглашения (см. 3.1) | Сообщение «Вы уже вошли» (или перепривязка при другом профиле) | То же |
| `/app` | — | Кнопка открытия Student App | Кнопка открытия Admin App |
| `/web` | — | Одноразовая ссылка входа в браузере (10 минут) | То же |
| `/today` | — | Уроки на сегодня и ближайшие | Сводка «Сегодня» |
| `/hw` | — | Мои ДЗ: активные | Очередь «На проверку» |
| `/help` | Справка | Справка | Справка |
| `/logout` | — | Отвязка аккаунта (с подтверждением) | То же |

Меню команд (BotFather `setMyCommands`) задаётся отдельно по состоянию пользователя через `BotCommandScopeChat`.

## 3. Сценарии

### 3.1. Принятие приглашения (`/start inv_<token>`)
1. Бот извлекает токен, считает SHA-256, ищет в `auth_tokens` (`purpose = invite`).
2. Токен недействителен (нет/просрочен/использован/отозван) → «Ссылка недействительна или устарела. Попросите у преподавателя новую». Счётчик неудач по `telegram_id` и IP ограничивается rate limiter.
3. У профиля уже есть другой `telegram_id` → бот просит подтверждение через инлайн-кнопки «Да, привязать этот аккаунт» / «Отмена» (FSM `ConfirmRelinkState`). После подтверждения старая привязка снимается, запись в `audit_log`.
4. Этот `telegram_id` уже привязан к другому профилю → отказ: «Этот Telegram-аккаунт уже привязан к другому профилю. Сообщите преподавателю».
5. Успех: `users.telegram_id` обновляется, токен помечается `used_at`, отправляется приветствие и показывается меню по роли. Персонал получает уведомление «Ученик X подключился».

### 3.2. Первый владелец
При запуске, если в БД нет `owner`, а в `.env` задан `OWNER_TELEGRAM_ID`, создаётся владелец (`display_name` = «Владелец», позже редактируется). Других способов стать владельцем нет.

### 3.3. Приглашение сотрудника
Владелец создаёт приглашение в Admin App с ролью `manager`; процесс аналогичен 3.1.

### 3.4. Каталог услуг (гость, а также доступно всем)
- Кнопка «Каталог услуг» → сообщение с первой карточкой (название, описание, стоимость текстом) и инлайн-кнопками «◀ Назад», «Далее ▶», «Связаться с преподавателем».
- Листание редактирует то же сообщение (`edit_message_text`), не создаёт новых.
- Если каталог пуст → «Каталог скоро появится. Напишите преподавателю».
- «Связаться» — URL-кнопка на `TEACHER_CONTACT_URL`.

### 3.5. `/logout`
Подтверждение «Вы уверены? Чтобы войти снова, понадобится новая ссылка от преподавателя» → `telegram_id = NULL`, запись в `audit_log`, переход в состояние гостя. **Владелец (`owner`) отвязать себя не может** (иначе он не сможет войти снова): бот отвечает отказом.

### 3.6. Быстрый просмотр
- `/today` для ученика: уроки в ближайшие 24 часа (время, предмет, ссылки Телемоста и доски кнопками), ДЗ с дедлайном сегодня.
- `/hw` для ученика: список активных ДЗ с дедлайнами и кнопкой «Открыть в приложении» (deep link в Student App на нужное ДЗ).
- Для персонала `/today`: данные `DashboardService` (T7.03) — уроки дня (в том числе отменённые, с пометкой) и блоки «ДЗ на проверку», «Не сдано к сегодняшним урокам», «Уроки без отметки», «Дедлайны ближайших 24 часов»; пустой день — «На сегодня уроков нет.». Строки про деньги в `/today` нет; «Заработано в этом месяце» приходит только владельцу в утренней сводке.

## 4. FSM (Aiogram + Redis storage)
FSM используется только для коротких диалогов. Состояния и данные хранятся в Redis с TTL 1 час.

| FSM | Состояния | Назначение |
|---|---|---|
| `ConfirmRelinkState` | `waiting_confirm` | Подтверждение перепривязки по приглашению |
| `LogoutState` | `waiting_confirm` | Подтверждение `/logout` (можно реализовать колбэками без FSM) |

Вход по логину и паролю отсутствует. Любое сообщение вне сценария получает подсказку «Воспользуйтесь меню или командой /help».

## 5. Клавиатуры

### 5.1. Главное меню (ReplyKeyboard, постоянное)
- **Гость:** «Каталог услуг», «Связаться с преподавателем».
- **Ученик:** «Открыть приложение», «Расписание», «Мои ДЗ».
- **Персонал:** «Открыть Admin App», «Сегодня», «На проверку».

> ⚠ Кнопка «Открыть приложение» / «Открыть Admin App» в **ReplyKeyboard — обычная текстовая**, не `web_app`. Telegram **не передаёт `initData`** Mini App, открытому кнопкой клавиатуры (такие Mini App рассчитаны на `sendData`), и вход через `POST /auth/telegram` не работает. По нажатию (и по команде `/app`) бот присылает сообщение с **инлайн-кнопкой `web_app`**: Mini App, открытый ею, получает `initData`. Это решение найдено при проверке на реальном Telegram (T1.16).

> **Этапность.** Реализовано: кнопка открытия приложения (ученик и персонал), кнопки гостя (T1.11), кнопки «Расписание» (ученик) и «Сегодня» (персонал) и команда `/today` (T3.08), уведомление `student_joined` (T5.06), кнопки «Мои ДЗ» (ученик) и «На проверку» (персонал) и команда `/hw` (аудит 2026-10-08, п. 5): ученику — активные ДЗ со сроком, каждое с инлайн-кнопкой `web_app` «Открыть в приложении» на `/app/homework/{id}`; персоналу — число работ на проверке и пять самых давних с кнопкой «Открыть Admin App».

### 5.2. Инлайн-кнопки
- Навигация каталога («Назад», «Далее»). Реализовано (T8.02): `callback_data` вида `cat:<номер карточки с 0>`, сообщение обновляется через `edit_text`, список перечитывается при каждом нажатии (номер приводится к допустимому); неопубликованные карточки не показываются.
- Уведомления: кнопки действий, например «Открыть ДЗ» (deep link), «Открыть Телемост».
- Подтверждения: «Да / Отмена».

### 5.3. Deep links в Mini App
Инлайн-кнопки `web_app` ведут на маршруты фронтенда: ученик — `https://<domain>/app/...` (например, `/app/homework/123`), персонал — `https://<domain>/admin/...`. Адрес нужен только для навигации: права всегда проверяются заново на сервере. Маршруты описаны в `12_frontend_guide.md`, часть 5.

## 6. Уведомления

Бот — транспортный слой. Решение о том, что и когда отправить, принимают сервисы и воркер (см. `03`, раздел 8). Бот не содержит таймеров.

### 6.1. Ученику
| Тип (`type`) | Когда | Срочное | Текст (пример) |
|---|---|---|---|
| `lesson_reminder` | за 30 минут до начала | да | «⏰ Через 30 минут урок: Информатика, 17:00. [Телемост] [Доска]» |
| `homework_deadline` | за 24 часа до `due_at`, если статус `assigned`/`needs_revision` | нет | «📌 Завтра дедлайн ДЗ «Название». Не забудьте сдать» |
| `homework_graded` | после оценки | нет | «✅ ДЗ «Название» проверено: 11/13» |
| `homework_returned` | возврат на доработку | нет | «↩ ДЗ «Название» нужно доработать. Комментарий: …» |
| `homework_assigned` | выдано новое ДЗ | нет | «📝 Новое ДЗ: «Название». Срок: …» |
| `lesson_cancelled` | отмена урока | да, если до урока < 12 ч | «❌ Урок 14 окт, 17:00 отменён» |
| `lesson_rescheduled` | перенос урока | да, если новое или старое время < 12 ч | «🔁 Урок перенесён: было …, стало …» |

### 6.2. Персоналу (owner и manager)
| Тип | Когда | Срочное |
|---|---|---|
| `homework_submitted` | ученик сдал ДЗ | нет |
| `homework_expired` | выдача перешла в `expired` | нет |
| `lesson_unmarked` | через 1 час после окончания урока нет отметки | нет |
| `morning_digest` | 08:00 по поясу получателя | нет |
| `student_joined` | ученик принял приглашение | нет |

### 6.3. Утренняя сводка (08:00)
Одно сообщение: уроки на сегодня (время, предмет, ученики); ДЗ на проверку (количество и топ-5); ученики с несданным ДЗ к сегодняшним урокам; уроки без отметки за прошлые дни; ДЗ с дедлайном в ближайшие 24 часа. Кнопка «Открыть Admin App». Для `owner` дополнительно строка «Заработано в этом месяце: N ₽».

### 6.4. Правила доставки
- **Тихие часы** 22:00–08:00 по `users.timezone` получателя. Несрочные уведомления переносятся на 08:00 (`scheduled_for`). Срочные отправляются сразу.
- **Дедупликация:** `dedup_key` уникален. Примеры: `lesson_reminder:{lesson_id}:{student_id}:{start_epoch}`, `homework_deadline:{assignment_id}:{due_epoch}`, `morning_digest:{user_id}:{yyyy-mm-dd}`.
- **Блокировка бота:** `TelegramForbiddenError` → `users.bot_blocked = true`, уведомление `skipped`; в Admin App у ученика отображается значок «бот заблокирован».
- **Повторы:** при сетевых ошибках до 3 попыток с паузой 1, 5, 15 минут.
- **Ограничения Telegram:** отправлять не быстрее ~25 сообщений/сек (на масштаб проекта не критично, но воркер использует небольшую паузу).
- **Отмена:** при отмене/переносе урока ожидающие напоминания для старого времени становятся неактуальными: диспетчер перед отправкой перепроверяет актуальность (`start_epoch` совпадает с текущим временем урока, урок `scheduled`) и иначе ставит `skipped`.

## 7. Webhook и polling
- `BOT_MODE=webhook` (prod/staging): эндпоинт `POST /telegram/webhook/{secret}`, где `{secret}` — секретный сегмент, производный от `WEBHOOK_SECRET` (отдельная переменная не нужна: `sha256("webhook-path:" + WEBHOOK_SECRET)[:32]`); дополнительно проверяется заголовок `X-Telegram-Bot-Api-Secret-Token`. `WEBHOOK_URL` — базовый адрес `https://<домен>/telegram/webhook`, секретный сегмент добавляется при `setWebhook` автоматически. Неверный путь → `404`, неверный заголовок → `403`.
- `BOT_MODE=polling` (local).
- Типы апдейтов ограничиваются (`allowed_updates`): `message`, `callback_query`, `my_chat_member`.
- `my_chat_member` с `kicked` помечает `bot_blocked`.

## 8. Тексты
Все пользовательские тексты бота и сообщений об ошибках лежат в `src/core/texts.py` (константы и функции форматирования). Язык — только русский. Тон текстов задаёт `docs/07_design.md` §8 (он приоритетнее этого раздела): ученику — на «ты», персоналу — нейтрально, без родовых окончаний. Формулировки утверждаются владельцем.

## 9. Обработка ошибок в боте
- Глобальный error handler Aiogram: логирует `ERROR` с трейсбеком, отправляет в Sentry, пользователю — «Что-то пошло не так. Попробуйте позже».
- `BusinessRuleError`, `PermissionDeniedError` и др. — понятные сообщения из `texts.py`.
- Колбэк-кнопки всегда отвечают `callback.answer()` (убирает «часики»).

## 10. Что бот не делает в MVP
- Не принимает файлы ДЗ в чате (загрузка через Mini App).
- Не принимает платежи.
- Не выполняет административные операции (создание уроков, учеников, оценка) — только через Admin App.
- Не использует логин/пароль.
